# AI Analysis Disclaimer Validation Fix

## Goal

Fix the `gpt-4o-mini` article-analysis failures caused by treating fixed disclaimer copy as model-generated structured output. Preserve strict validation for the actual analytical fields while storing a deterministic, server-controlled disclaimer for every new analysis.

## Skills read

- `.agents/skills/ai-sdk/SKILL.md`

## Existing code inspected

- `AGENTS.md`
- `lib/ai/article-analysis.ts`
- `lib/analysis/pipeline.ts`
- Installed AI SDK structured-output documentation and source under `node_modules/ai/`

## Decisions and assumptions

- The earlier diagnostic probe established that `gpt-4o-mini` can return the required analytical object, but its natural disclaimer wording fails the two custom disclaimer refinements.
- Disclaimer text is product copy rather than an article-dependent analytical result, so it should not be generated by the model.
- Use one exported server-only constant containing both an explicit AI attribution and an uncertainty statement.
- Do not weaken validation of summaries, sentiment, framing percentages, confidence, framing notes, or loaded terms.
- Do not change existing database columns, Supabase types, API request shape, batching, embeddings, or completion semantics.

## Files likely to change

- `lib/ai/article-analysis.ts`
- `lib/analysis/pipeline.ts`

## Implementation requirements

1. Add an exported `ANALYSIS_DISCLAIMER` constant to `lib/ai/article-analysis.ts` with concise user-facing language explaining that the analysis is AI-generated, is an estimate based only on article text, and may contain errors.
2. Remove `disclaimer` from `articleAnalysisSchema`, including its custom wording refinements, so the model is no longer responsible for fixed product copy.
3. Allow `GeneratedArticleAnalysis` to continue being inferred from the reduced schema.
4. Import `ANALYSIS_DISCLAIMER` into `lib/analysis/pipeline.ts`.
5. Persist `ANALYSIS_DISCLAIMER` in `saveArticleAnalysis` instead of reading `generated.disclaimer`.
6. Keep `gpt-4o-mini`, `text-embedding-3-small`, retry behavior, and all remaining Zod validation unchanged.
7. Avoid unrelated refactors.

## Security requirements

- Keep the analysis module server-only.
- Do not expose or log `OPENAI_API_KEY`, Supabase service credentials, the admin secret, article bodies, or raw model output.
- Keep OpenAI calls and persistence exclusively on the server.
- Do not place secrets in test commands or committed files.

## Acceptance criteria

- Structured generation no longer requests or validates a model-authored disclaimer.
- Every newly saved analysis receives the same server-controlled disclaimer.
- All analytical fields retain their existing strict validation.
- Existing `article_analyses.disclaimer` persistence remains compatible; no migration is necessary.
- TypeScript, ESLint, and the production build succeed.
- A one-article `/api/analyze` request no longer fails due to disclaimer wording.

## Exact manual test steps

1. Start the application and watch its terminal for analysis progress:

   ```powershell
   npm run dev
   ```

2. Set the local admin secret without printing it:

   ```powershell
   $env:BIASLY_ADMIN_SECRET = "<same value as .env.local>"
   ```

3. Analyze one pending article first:

   ```powershell
   curl.exe -X POST "http://localhost:3000/api/analyze" `
     -H "Content-Type: application/json" `
     -H "x-biasly-admin-secret: $env:BIASLY_ADMIN_SECRET" `
     -d '{"limit":1}'
   ```

4. Confirm the response reports one analyzed and embedded article with no analysis-generation failure, and confirm the stored analysis contains the deterministic disclaimer.

5. Process all remaining pending work:

   ```powershell
   curl.exe -X POST "http://localhost:3000/api/analyze" `
     -H "Content-Type: application/json" `
     -H "x-biasly-admin-secret: $env:BIASLY_ADMIN_SECRET" `
     -d '{}'
   ```
